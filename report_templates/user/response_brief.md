## 模板说明

# 处置建议专报

**一句话说明：** 将研判结果转成分级、可执行、可跟踪的处置建议，适合需要明确下一步动作的场景。

| 项目 | 说明 |
| --- | --- |
| 适合场景 | 舆情回应、风险处置、跨部门协同和领导批示办理 |
| 预计篇幅 | 约 600～900 字，优先保证动作清楚 |
| 固定结构 | 当前问题、处置目标、建议措施、跟踪指标 |

## 使用特点

- 建议从当前问题出发，先说明要解决什么，再安排动作。
- 每项措施尽量包含责任对象、时序或验收信号，便于落地。
- 不替管理部门做未经授权的最终决策；无法确定的责任归属要标注待确认。
- 只需要分析、不需要行动清单时，选择灵活助手或决策备忘录。

# 俄乌冲突舆情处置建议专报

## 当前问题

俄乌冲突信息来源复杂，军事动态、外交表态、人道议题和经济影响相互交织。交战方对战果、损失及责任归属的表述存在差异，社交平台还存在旧图重发、来源不明视频和情绪化标题，容易干扰事实判断。

## 处置目标

优先确保重点信息可核验、单方主张有归属；阶段性形成军事、外交、人道、核安全和能源粮食议题的连续监测；避免将传播热度误判为事件真实性或趋势确定性。

## 建议措施

1. **优先：** 对伤亡数字、即时战线和所谓“重大转折”执行双源核验，未确认内容不进入结论。
2. **阶段：** 将“俄方称”“乌方称”和国际组织公开材料分栏记录，保留时间与原始出处。
3. **常态：** 跟踪援助制裁、谈判信号、黑海运输、能源供应及核设施安全，按议题变化调整监测重点。

## 跟踪指标

观察权威渠道确认情况、单方信息被交叉验证的比例、高传播内容溯源完成情况，以及外溢议题是否出现集中升温。

## 选用后系统会怎么做

系统把当前研判转成行动清单，按“当前问题—目标—措施—指标”组织。建议必须来自材料和用户要求；没有明确责任或时间时，不擅自补全。

## 生成要求

1. 使用四个固定标题，并让每项建议回答“谁做、做什么、何时看结果”。
2. 区分立即、近期和持续动作；动作之间避免重复，优先列最可执行的 3～6 项。
3. 跟踪指标应能观察或核验；没有合适指标时写明需要业务人员确认。
4. 不编造授权、资源、效果、数字或机构立场；不得复制预览中的俄乌冲突事件名称、报告标题、日期、措施或研判结论。
5. 只输出最终 Markdown，不输出模板说明、思考过程、免责声明或重复总结。
