## 模板说明

# 要点清单

**一句话说明：** 先给少量核心结论，再用条目列出依据和关注事项，适合快速浏览。

| 项目 | 说明 |
| --- | --- |
| 适合场景 | 值班摘要、晨会通报、领导快速阅览 |
| 预计篇幅 | 约 400～650 字，通常不超过 8 个要点 |
| 表达方式 | 短句、动词开头、结论优先 |

## 使用特点

- 第一行说明当前最重要的判断，随后列出支持该判断的材料。
- 每条只表达一个事实或动作，合并重复内容，避免长段落。
- 对不确定内容使用“可能”“尚待核实”等准确措辞，不把推测写成事实。
- 需要完整背景、风险推演或正式建议时，应选择更长的模板。

### 俄乌冲突舆情要点

**核心判断：** 俄乌冲突相关舆情仍由军事动态、外交博弈、制裁援助和人道议题共同驱动，信息立场化与核验滞后是主要特征。

**主要依据**

- 俄乌双方对战果、损失及责任归属的表述差异明显，单方通报需明确归属。
- 黑海运输、能源供应、难民安置和核设施安全形成明显外溢关注。
- 社交平台存在旧图重发、来源不明视频和情绪化标题，不能以传播热度替代事实判断。

**关注事项**

- 跟踪重大军事行动、援助政策和谈判信号引发的舆情波动。
- 对伤亡数字、战线变化及所谓“独家消息”执行交叉核验。

## 选用后系统会怎么做

系统把检索材料压缩成少量可扫描的条目，优先保留会改变判断或行动的事实。材料不足时如实说明，不为了凑条数扩写。

## 生成要求

1. 开头用一句话给出核心判断，再提供 3～6 条主要依据或关注事项。
2. 每条控制在一到两句，使用短句和明确动词；同义信息合并。
3. 只有材料明确提供时才写数字、时间和来源；不确定内容注明待核实。
4. 预览只用于学习条目结构，不得复制其中的俄乌冲突事件名称、报告标题、日期、事实、数字或研判结论。
5. 只输出最终 Markdown，不输出模板说明、思考过程、免责声明或重复总结。
