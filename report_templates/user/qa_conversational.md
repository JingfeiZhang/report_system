## 模板说明

# 问答解读

**一句话说明：** 先正面回答用户的具体问题，再解释依据、边界和下一步，适合连续追问。

| 项目 | 说明 |
| --- | --- |
| 适合场景 | 明确问答、观点解释、对已有报告的局部追问 |
| 预计篇幅 | 约 600～900 字，问题简单时主动收缩 |
| 表达方式 | 结论先行，必要时用编号说明依据 |

## 使用特点

- 首段必须让读者直接看到问题的答案，不先铺长背景。
- 后续只解释与答案相关的材料、推理和不确定性。
- 用户的问题范围不清时，说明当前可判断范围，并提出最少的补充信息。
- 需要正式归档或完整长文时，应改选四段式报告或决策备忘录。

### 研判俄乌冲突舆情应重点关注什么？

**直接回答**

应重点关注军事消息的真实性、外交与援助政策变化、人道和核安全风险，以及能源粮食议题的外溢影响。俄乌冲突信息来源多、立场差异大，不能根据单一账号、单方通报或短时热度形成确定判断。

**依据与解释**

1. **信息核验：** 俄乌双方对战果、损失和责任归属的叙述并不一致，相关内容应注明“俄方称”或“乌方称”，并等待独立来源补充。
2. **风险外溢：** 难民安置、黑海运输、能源供应和扎波罗热核电站安全等议题，可能跨越战场范围影响国际舆论。
3. **传播特征：** 旧图重发、视频移花接木和情绪化标题容易在社交平台扩散，热度本身不等于事实可靠。

**下一步**

围绕军事、外交、人道、核安全和能源粮食五类议题开展分类监测，并对伤亡数字、即时战线及所谓“重大转折”进行交叉核验。

## 生成要求

## 选用后系统会怎么做

系统优先回答本轮问题，再从检索摘要、知识库和会话上下文中挑选必要依据。简单问题不扩写成长报告，复杂问题也只围绕问题展开。

## 生成要求

1. 第一段直接回答问题；不确定时明确给出判断边界，不用肯定语气掩盖证据不足。
2. 后续用 2～4 个编号或小标题说明依据、差异和必要的补充信息。
3. 不擅自扩大主题，不编造数字、时间、机构观点或来源；冲突材料并列说明。
4. 预览只用于学习问答结构，不得复制其中的俄乌冲突事件名称、报告标题、日期、事实、数字或研判结论。
5. 只输出最终 Markdown，不输出模板说明、思考过程、免责声明或重复总结。
